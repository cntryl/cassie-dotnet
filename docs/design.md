# Provider design direction

The provider implements Cassie's documented PostgreSQL wire contract directly, with an idiomatic `System.Data.Common` API. It does not depend on another PostgreSQL client. Runtime dependencies are limited to .NET, official Microsoft libraries, and Cntryl libraries. Test tooling uses the approved xUnit framework, Microsoft Testing Platform, and Cntryl convention packages; the benchmark runner has no external dependencies.

The end state follows Cassie's product roadmap and the compatibility profile Cassie promotes for its v1.0 production release. The provider must support the SQL, type, catalog, session, and client workflows in that profile, including every documented text and binary wire format, streaming and multi-result queries, parameter binding, transactions and savepoints, cancellation, TLS, and CSV `COPY FROM STDIN`. Integrations for capabilities Cassie still marks Experimental remain opt-in until Cassie promotes them. Cassie's permanent exclusions remain exclusions for this provider: full PostgreSQL parity, distributed SQL, native extension loading, general stored-program execution, triggers, replication, and unsupported isolation or SQL forms are not provider goals. The documented limited one-statement `CALL` workflow is supported. Provider-side ADO.NET features include safe pooling, async cancellation for queries and transaction start, asynchronous disposal and prepared-statement cleanup, reader/command behavior, database switching across startup sessions, and typed access to supported Cassie values.

Design for narrow responsibilities, explicit composition, streaming, cancellation and recovery, secure TLS defaults, structured logging, `ActivitySource` and `Meter` instrumentation, trimming and Native AOT. Do not claim these capabilities until implemented and verified. SQL text, parameters and credentials must not be emitted by default.

The Cassie pgwire writer now tracks settings already reported to each connection and sends only changed `ParameterStatus` values after statement results, before `ReadyForQuery`. This covers changes made by SQL commands and `set_config` calls inside stored views. Tests verify updates between statements in a simple-query batch and after rows from simple, view, and extended queries, so each result is decoded with the DateStyle used to serialize it.

The provider tracks `ReadyForQuery` transaction status. It defers its `SHOW DateStyle` fallback while a transaction is failed, so recovery commands such as `ROLLBACK` can reach Cassie, and invalidates the cached style after `COMMIT` or `ROLLBACK` in case `SET LOCAL` was restored. It consumes `ParameterStatus` frames in query and COPY response streams. `GetOrdinal` prefers an exact column-name match before its case-insensitive fallback. Connection startup values, SQL text, and COPY command text reject embedded NUL characters before pgwire framing. The Release solution build passed with zero warnings and zero errors.
